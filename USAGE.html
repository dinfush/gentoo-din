gentoo-din Overlay 操作使用与双仓库解耦指南

适用于普通机器生产挂载与本地维护机“开发/使用物理隔离”的标准手册

1. 仓库定位与核心规范

gentoo-din 是公开托管在 GitHub 上的定制个人 Overlay，专注实现非 systemd（如 OpenRC）环境下的纯净体验与内核原生 SUID TUN 网卡能力。

  • 云端源码: https://github.com/dinfush/gentoo-din.git
  • 稳定关键字: 固化使用 KEYWORDS="amd64 arm64"，免去繁琐的 package.accept_keywords 配置。
  • 包名与覆盖原则: 严禁更改包名（不加 -din 后缀），完全依托 Portage 原生 priority 仲裁机制优先选用。

2. 生产环境接入（普通客户端机器）

在任意一台作为终端使用（无需写 ebuild）的 Gentoo 宿主机上，仅需接入云端 Git 仓库：

# 1. 注册并添加云端仓库（只需执行一次）
sudo eselect repository add gentoo-din git https://github.com/dinfush/gentoo-din.git

# 2. 确保在 /etc/portage/repos.conf/gentoo-din.conf 中配置了最高仲裁优先级
[gentoo-din]
location = /var/db/repos/gentoo-din
sync-type = git
sync-uri = https://github.com/dinfush/gentoo-din.git
priority = 9999
auto-sync = yes

后续日常完全像使用官方 guru 一样执行常规同步：

# 单库更新
sudo emaint sync -r gentoo-din

# 随系统全量更新
sudo emaint sync --auto

3. 本地维护机：双仓库物理隔离模式（开发与使用互不干扰）

为什么采用双仓库模式？

解决“开发目录被 Portage 缓存与 root 权限文件污染”以及“系统日常使用必须保证与 GitHub 云端一致”的痛点。无需反复修改配置文件中的 location 路径！

配置方式：保持两个配置文件共存

配置 A：系统正式源 /etc/portage/repos.conf/gentoo-din.conf（严格拉取 GitHub 云端）：

[gentoo-din]
location = /var/db/repos/gentoo-din
sync-type = git
sync-uri = https://github.com/dinfush/gentoo-din.git
priority = 9999
auto-sync = yes

配置 B：本地开发调试源 /etc/portage/repos.conf/gentoo-din-dev.conf（直连本地 Workspace）：

[gentoo-din-dev]
location = /home/din/Workspace/gentoo/gentoo-din
priority = 10000
auto-sync = no
优先级逻辑说明：

本地开发源（priority = 10000）> 系统云端源（priority = 9999）> 外部仓库（0）> 官方 Gentoo（-1000）。

4. 双仓库工作流全景图

  • 场景 1：本地编写与调试 ebuild 时
    1. 在 ~/Workspace/gentoo/gentoo-din 目录下改动、新增 ebuild 并生成 digest。
    2. 运行 sudo egencache --repo=gentoo-din-dev --update 刷新本地调试源缓存。
    3. 凭借 priority = 10000，此时 emerge 测试的是本地工作区最新的改动。
  • 场景 2：调试完成，推送云端上生产
    1. 矫正工作区文件归属：sudo chown -R ${USER}:${USER} .
    2. 提交并推送到远端：git commit && git push origin main。
  • 场景 3：系统纯净正式拉取（验证云端体验）
    1. 执行 sudo emaint sync -r gentoo-din，系统正式将远端更新拉入 /var/db/repos/gentoo-din。
    2. 平时不开发时，系统直接与 GitHub 保持绝对一致，两套环境物理隔离，干净纯粹。

5. 软件安装与验证命令

# 预检版本来源与 USE 状态（应显示 +tun -systemd 且来源明确）
emerge -pv net-proxy/clash-verge-bin
emerge -pv net-proxy/mihomo-party-bin

# 直接安装
sudo emerge -av net-proxy/clash-verge-bin
